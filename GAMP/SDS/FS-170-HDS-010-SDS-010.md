# FS-170-HDS-010-SDS-010 Image Analysis Sessions

The analysis action is a single host-side program with four subcommands:
`mount`, `collect`, `umount`, and `status`, plus `list`.

Sessions are keyed by the SHA-256 of the canonical (symlink-resolved) image
path, so two analyses of the same image cannot attach it twice, and two
different images never share state. Each session directory under the runtime
state root holds one JSON record: schema version, image, attached device,
mountpoint, filesystem, detected label, and creation time.

`mount` validates the image as an existing regular file, attaches it read-only
over NBD, waits for the block device to become readable, probes for the guest
root filesystem, and mounts it read-only if mounting is permitted. It reuses an
existing live session instead of attaching again. A session record whose
mountpoint is no longer mounted is treated as stale and replaced.

`collect` reuses a live session or creates one, copies a defined artifact set
(or the explicit `--path` list) into a destination directory preserving absolute
paths, writes a JSON manifest listing collected and absent artifacts, and
releases the session it created. An explicit `--no-mount` selects filesystem
extraction without mounting.

`umount` releases the mount and the device using only the recorded session, and
is idempotent: an absent session is success. A busy mountpoint leaves the
session intact and reports failure rather than silently detaching a device still
in use.

Input that is not an existing regular file, or that yields no supported
filesystem, fails explicitly without leaving an attachment behind.

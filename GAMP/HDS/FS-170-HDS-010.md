# FS-170-HDS-010 Offline Read-only Image Attachment Environment

The analysis action runs on the VM host as root against a host-local image file
in the manager's runtime or persistent storage class.

The image is exposed as a read-only block device (QEMU NBD export with the
read-only flag) so the read-only property is enforced by the attachment itself
and not only by the mount options. The guest root filesystem is located by
probing the device and any partitions rather than by assuming a layout. The root
is then mounted read-only, or, where mounting is unavailable, read through an
ext-filesystem reader that performs no writes.

Per-image session state is recorded on the host under `/run`, holding the
attached device, mountpoint, and detected filesystem. Release uses only that
recorded state, so it remains possible after the analysing process has exited.
Attachment requires an available NBD device; the host must provide the `nbd`
kernel module. Where no NBD device is available, no read-only attachment is
claimed and the action fails explicitly.

Writable access, guest execution, guest networking, and any modification of the
image or its backing file are outside this boundary.
